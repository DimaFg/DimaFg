# Безопасность, секреты и персональные данные

## Секреты

- В Git не попадают `.env`, токены бота, пароли SMTP и БД, `APP_SECRET`, дампы и резервные копии.
  `.gitignore` защищает только от новых коммитов: если секрет уже попал в историю, его нужно
  сначала отозвать и перевыпустить, затем вычистить историю.
- В production секреты задаются через secret store или защищённые переменные окружения хостинга.
  Локально — `chmod 600 .env`.
- В коде секреты хранятся как `SecretStr` и не выводятся в `repr` настроек и логах.
- `APP_SECRET` — ключ HMAC для отпечатков IP. Его ротация сбрасывает лимиты частоты заявок.
- S3-ключ (этап «Медиа») получает права только на нужные bucket и операции.

## Персональные данные в логах

- Имя, контакт, сообщение и внутренняя заметка в логи не пишутся. Для диагностики служат
  `request_id`, `lead_id` и публичный номер заявки.
- SQLAlchemy работает с `hide_parameters=True`: иначе значения запроса — то есть данные заявки —
  попадают в текст исключений и traceback.
- `JsonFormatter` дополнительно заменяет на `[redacted]` поля с персональными данными и поля,
  похожие на секреты (`token`, `password`, `secret`, …).
- Access-лог uvicorn отключён: собственный middleware пишет метод, путь без query string и статус.
- Docker хранит логи с ротацией: 5 файлов по 10 МБ на контейнер.

## База данных

- PostgreSQL доступен только во внутренней сети Compose, наружу открыты лишь 80/443 Caddy.
- Для production — отдельный пользователь БД с минимальными правами, шифрование дисков и бэкапов,
  регулярная проверка восстановления (`docs/backup-restore.md`, этап Production).
- Заявки и фото не удаляются из интерфейса физически: сначала архивирование, затем очистка
  контролируемой задачей по сроку хранения.

## Проверка перед выпуском

1. `git status` не показывает `.env`, дампы и логи. История Git проверена сканером секретов.
2. Тестовые токены ротированы; в `.env` production нет значений `dev-*`
   (приложение откажется стартовать с dev-значением `APP_SECRET`).
3. В политике конфиденциальности заполнены оператор, контакты и сроки хранения, текст проверен юристом.
4. `docker compose ps` показывает `healthy` для `api` и `worker`.
5. Проверено восстановление из резервной копии.
