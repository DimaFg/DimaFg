## Сверка с attendance-bot (Arsgaz/attendance-bot)

Взято из него:

- **Утечка персональных данных в логи — найдена и исправлена.** Исключения SQLAlchemy включали значения запроса (имя, контакт, сообщение заявки), а обработчик ошибок писал traceback в лог. Теперь `hide_parameters=True`, есть регрессионный тест.
- Фильтр полей лога по образцу `observability/privacy.py`.
- `SecretStr` для токенов и паролей.
- Heartbeat worker'а и healthcheck контейнера (`python -m app.cli healthcheck`), который проверяет БД, совпадение ревизии Alembic с кодом и свежесть heartbeat. Зависший worker теперь становится `unhealthy`.
- В Compose: `init: true`, ротация json-логов, `start_period`.
- Настраиваемые параметры повторов outbox (`OUTBOX_RETRY_BASE_SECONDS`, `OUTBOX_RETRY_MAX_SECONDS`, `OUTBOX_LOCK_TIMEOUT_SECONDS`).
- `SECURITY.md`.

Взять на этапе Production:

- **Резервное копирование.** Их сервис `backup` — образец: проверка целостности перед упаковкой, хранение 7 ежедневных и 4 еженедельных снимков, `pre-restore` снимок перед восстановлением, heartbeat и тесты. Для нас — то же поверх `pg_dump` с выгрузкой копий вне VPS.

Архитектура после рефакторинга:

- Модульный монолит сохранён. Внутри backend выделены `domain`, `application`, `port`, `adapter`, `presentation` и `di` по образцу attendance-bot и event-service. Это не противоречит ТЗ: слои описывают зависимости внутри приложения, а монолит — способ его развёртывания.
- Создание заявки и доставка уведомления отделены от FastAPI и SQLAlchemy. Простой публичный каталог читается через порт с проекциями без дополнительных доменных агрегатов.
- Зависимости собираются в `di` через FastAPI Depends; отдельный DI-контейнер пока не требуется.

Сознательно не перенесено:

- structlog. Наш JSON-логгер на stdlib покрывает те же задачи без зависимости.
- SQLite: у нас PostgreSQL по ТЗ.

Подробнее: [архитектура](./architecture.md).

У нас уже есть то, что у них ещё в плане: CI с `alembic check`, graceful shutdown worker'а, дедупликация повторных запросов, непривилегированный пользователь в Docker-образе.

## Решения, принятые по ходу

- **Отверстия перфорации не выводятся.** В прототипе стили `.hole` есть, но в разметке их нет — полосы по краям пустые. Сохранено как в прототипе; включить — одна строка в `FilmChrome.tsx`.
- **Заголовок hero на узких экранах масштабируется по ширине.** В прототипе на 375 px слово «Монументальность» выходило за экран и давало горизонтальную прокрутку.
- **Кнопка меню поверх открытой панели.** В прототипе панель перекрывала кнопку, и закрыть меню можно было только выбором пункта.
- **Подсказка над сеткой** на сенсорных экранах: «Нажмите на кадр, чтобы открыть» вместо «Наведите…».
- **Пояснение-заглушка под формой** заменено текстом о том, что заявки не теряются.
- **`partialPrefetching` выключен**: с ним первый запрос к несуществующему адресу получал 200 вместо 404.
- **Контент услуг и категорий пока продублирован** в `web/src/features/*/data/demo.ts` и `api/app/seed/data.json`. Страницы, metadata и sitemap читают его через `web/src/lib/catalog.ts`. Когда появится админка услуг, источник каталога будет заменён на API.
- **Цвет `--muted-2` (#5f594d)** не проходит контраст WCAG AA для текста — оставлен для декора, для служебного текста футера взят чуть светлее `--muted-text`.
