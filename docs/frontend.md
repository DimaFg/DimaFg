# Устройство фронтенда

Фронтенд остаётся небольшим Next.js-приложением. Разделение по функциям упрощает навигацию
без дополнительных библиотек состояния, UI-фреймворков и множества формальных слоёв.

| Каталог | Ответственность |
|---|---|
| `app` | Маршруты, metadata, sitemap, композиция страниц |
| `features/leads` | Представление формы, хук состояния, валидация, ошибки, атрибуция и POST API |
| `features/portfolio` | Фильтры, сетка, просмотр фото, типы и демонстрационные данные |
| `features/services` | Карточки услуг, формат цены, типы и демонстрационные данные |
| `components/layout` | Шапка, футер, декоративная рамка сайта |
| `components/home` | Статические секции о фотографе и hero |
| `shared/ui` | Reveal, JsonLd, PageHero |
| `shared/lib` | Общие accessibility-хуки |
| `lib/catalog.ts` | Единая серверная точка чтения каталога |
| `lib/api/schema.ts` | Типы, генерируемые из OpenAPI; вручную не редактируются |

Внутри функции используются обычные импорты. Общая папка `shared` предназначена для
действительно переиспользуемого кода. Специфичные для услуги или фотографии типы
находятся рядом с соответствующей функцией.

## Форма

`LeadForm` содержит разметку. `useLeadForm` управляет состоянием, отправкой, повторными
попытками и фокусом. Валидация и преобразование ошибок выделены в отдельные функции.
HTTP-клиент использует сгенерированные типы API. Через границу Server/Client Components
в форму передаются только slug и подпись услуги.

После сетевой ошибки повтор с теми же нормализованными данными сохраняет ключ
идемпотентности. Изменение данных заявки создаёт новый ключ. Пробелы по краям полей
не меняют идентичность заявки. Время заполнения и атрибуция не влияют на ключ.

Если первый запрос фактически сохранился, но ответ потерялся, изменённая отправка может
создать отдельную заявку. Она не должна молча подтверждаться как прежняя: сервер по
старому ключу возвращает исходный результат независимо от нового тела запроса.

## Каталог

Страницы, metadata и sitemap получают каталог через `lib/catalog.ts`. Пока источник —
прежние демонстрационные данные: переключение на неполный API изменило бы содержание
сайта. Карточки и форма не загружают эти данные самостоятельно.

Когда API наполнится реальным контентом, адаптер каталога должен преобразовать
сгенерированные API-типы в модели представления. Это позволит подключить backend
без переноса snake_case-полей и транспортной логики в компоненты. Дублирование контента
услуг с backend seed пока сохраняется; подключение API — отдельный этап.

## Внешний вид

CSS перенесён к компонентам без изменения содержимого. Порядок подключения в layout
сохранён, чтобы не изменить каскад. Базовые стили и общие стили страниц остались
в `src/styles`. Миграция на CSS Modules сейчас не выполнялась.

Декоративное заполнение последнего ряда галереи сохранено, включая прежний расчёт для
трёх колонок на мобильном экране с двумя колонками. Его исправление меняет композицию,
поэтому отложено по требованию сохранить внешний вид.

Проверка рефакторинга: снимки главной, контактов, портфолио и страницы личной съёмки
на ширинах 375 и 1440 px полностью совпали до и после изменений в одном Chromium
с отключёнными анимациями. Это проверка этих страниц и размеров, а не всех браузеров.

## Проверки

`npm run typecheck`, `npm run lint`, `npm run build` и `npm run test:e2e`.
Playwright проверяет повторы заявки с изменением и без изменения данных, валидацию,
фокус мобильного меню, lightbox и ответы 404. Запросы отправки заявки подменяются
в тестовом браузере, реальные заявки и уведомления не создаются.
